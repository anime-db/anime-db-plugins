# animedb-language-pack

Официальный языковой пакет AnimeDB — дополнительные языки интерфейса приложения.

Это **плагин типа `translation`**: чисто декларативный ресурс без кода. У него нет
`src/`, нет сервисов и нет фич — только манифест и каталоги переводов. Приложение
подхватывает его каталоги в свой домен `messages` и добавляет объявленные локали в
переключатель языка.

## Состав

```
animedb-language-pack/
├── manifest.json
├── README.md
└── translations/
    └── messages.de.yaml
```

## Домен каталога — `messages`, а не id плагина

Symfony выводит домен из имени файла: `<домен>.<локаль>.<формат>`. Плагины фич
(`integration`, `local`) возят **свои** строки и потому называют каталоги
`<plugin-id>.<locale>.yaml`. Плагин-перевод **расширяет ядро**, а ядро использует
единый домен `messages` — поэтому здесь `messages.<locale>.yaml`.

Каталог, названный `animedb-language-pack.de.yaml`, создал бы домен, который никто не
резолвит: файл лежит на месте, валидатор молчит, интерфейс не переведён ни на строку.

## Правила для каталогов

Часть правил гейтит `tools/src/PluginValidator.php` на каждом pull request, часть —
конвенция, за которой следит только автор перевода. Разница существенная: то, что не
проверяется машиной, ломается молча.

### Проверяет валидатор

- **Набор ключей одинаков во всех локалях пакета.** Пока локаль одна, сравнивать не с
  чем и проверка вырождается — она начнёт работать со второй локалью.
- **Плейсхолдеры Symfony-стиля `%…%`** (`%count%`, `%title%`, `%path%` и другие) —
  набор в строке совпадает по составу между локалями пакета. Имя плейсхолдера не
  переводится и не меняется. Порядок внутри строки свободен и подчиняется грамматике
  языка — сравнивается состав, а не последовательность.
- **Ни `|`, ни фигурных скобок** в значениях: первое — плюрализация Symfony, второе —
  ICU-синтаксис, ни того ни другого в проекте нет.
- **Каталог с суффиксом `+intl-icu`** в имени файла отклоняется по той же причине.
- **Пустых значений нет.** Отсутствующий перевод — дефект, а не фолбэк на другую
  локаль.
- **Манифестный `locales` совпадает с набором файлов `messages.<locale>.yaml`** в обе
  стороны: объявленная локаль без каталога и каталог без объявления — обе ошибки.
- **Домен каталога соответствует типу плагина** — для `translation` это `messages`.

### Не проверяет никто — соблюдать вручную

- **Совпадение набора ключей с эталонным каталогом ядра.** Каталог плагина ни с чем не
  сверяется: ядро лежит в другом репозитории, и сверить его отсюда нечем. Пакет с пятью
  ключами вместо трёхсот пройдёт всю валидацию. Больше того, при каждом релизе ядра с
  новыми строками пакет автоматически становится неполным, и узнать об этом сейчас
  неоткуда.
- **Счётные строки без грамматического согласования** — в стиле «подпись: число»
  (`Zu prüfen: %count%`). Такая форма верна при любом числе плюральных форм языка: 3 в
  русском, 2 в немецком, 1 в японском, 6 в арабском. Валидатор ловит `|` и фигурные
  скобки, но не отличит согласованную формулировку от несогласованной.
- **Терминология и смысл перевода.** Глоссарий проекта — в
  [`.claude-docs/conventions.md`](../../.claude-docs/conventions.md).

## Качество перевода

Русский и английский каталоги ядра ведёт автор проекта. Языки этого пакета —
**машинного качества, вычитки носителем не было**. Это осознанный компромисс
пет-проекта: пакет существует прежде всего как рабочий пример того, как устроен
плагин-перевод, и как проверка того, что механизм подключения локалей работает.

Если найдёте ошибку в переводе — правка приветствуется.
